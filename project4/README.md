# Project 4 — 페이지 교체와 스와핑

[전체 프로젝트 소개](../README.md)

## 목표

물리 메모리가 부족할 때 사용자 페이지를 스왑 공간으로 내보내고, 다시 접근하면 페이지 폴트를 통해 복구하는 page-level swapping을 구현했습니다. 수업에서 제공한 별도 스켈레톤을 바탕으로 작업했습니다.

## 구현 내용

- 교체 가능한 사용자 페이지를 원형 이중 연결 리스트로 관리합니다.
- Clock 정책으로 페이지 테이블 엔트리의 Accessed 비트를 확인하고 교체 대상을 고릅니다. 리스트 이름은 LRU이지만 교체 정책은 Clock입니다.
- `kalloc()`의 freelist가 비면 페이지를 회수하고 `swap_out()`으로 디스크에 기록합니다.
- PTE에 스왑 상태와 슬롯 정보를 기록하고, 페이지 폴트 시 `swap_in()`으로 물리 메모리에 복구합니다.
- 비트맵으로 스왑 슬롯을 관리하며, `fork()`와 메모리 해제 경로에도 스왑된 페이지 처리를 추가했습니다.
- 공유 리스트용 락과 메모리 할당기 락의 획득·해제 위치를 조정했습니다.

`swapread`, `swapwrite`, `swapstat` 및 스왑용 디스크 기반 기능은 과제에서 제공한 구성입니다. 개인 구현의 중심은 페이지 추적, 교체 대상 선정, swap-in/out 및 메모리 관리 경로의 연결입니다.

## 주요 코드

| 파일 | 확인할 내용 |
| --- | --- |
| [kalloc.c](kalloc.c) | 페이지 리스트, Clock hand, `reclaim`, 메모리 부족 시 회수 |
| [vm.c](vm.c) | 스왑 비트맵, `swap_out`, `swap_in`, 페이지 복사·해제 |

## 실행과 확인

빌드에 필요한 도구는 [루트 README](../README.md#빌드와-실행)를 참고합니다.

```sh
make clean
make CPUS=1 QEMU=qemu-system-i386 qemu-nox
```

xv6 셸에서 `swaptest`를 실행합니다. `swapstat()`의 두 출력은 스왑 공간 사용량이 아니라 **읽은 섹터 수와 쓴 섹터 수**입니다. 테스트 문자열에 `Swap space`라고 적혀 있지만 통계의 의미와 구분해야 합니다.

스와핑을 발생시키기 위해 [memlayout.h](memlayout.h)의 `PHYSTOP`을 `0x1000000`(16 MiB)으로 제한했습니다. QEMU의 `-m` 설정과 별도로 커널에서 사용하는 물리 메모리 상한입니다.

구현 중에는 페이지 리스트와 메모리 할당기의 락 때문에 발생하는 교착 문제를 GDB로 디버깅했습니다. 다중 CPU 부하 테스트는 추가로 필요합니다.

# Project 5 — 파일 시스템 확장

[전체 프로젝트 소개](../README.md)

## 기반 코드

Project 0의 기본 xv6 코드에서 파일 시스템을 확장했습니다. 단일 CPU 환경을 사용합니다.

## 목표와 구현 범위

기존 xv6 파일 시스템에 **이중 간접 블록(doubly indirect block)**을 추가해 파일 하나의 최대 크기를 확장했습니다. 과제는 파일 크기 확장과 Block Group 도입의 두 부분으로 구성된 선택·보너스 과제였습니다.

**파일 크기 확장을 구현했으며 Block Group은 미완성입니다.** Block Group 구현 중 문제가 발생해 작업을 중단했고, 관련 코드는 `fs.c`, `fs.h`, `param.h` 등에 주석으로 남겨두었습니다.

## 블록 주소 구조

| 구분 | 기존 xv6 | 확장 후 |
| --- | --- | --- |
| 직접 블록 | 12 | 11 |
| 단일 간접 블록이 가리키는 데이터 블록 | 128 | 128 |
| 이중 간접 블록이 가리키는 데이터 블록 | 없음 | 128 × 128 |
| 최대 데이터 블록 수 | 140 | 16,523 |
| 최대 파일 크기 | 71,680 bytes | 8,459,776 bytes (약 8.46 MB) |

블록 크기는 512 bytes이고 블록 번호는 4 bytes이므로 간접 블록 하나에 128개의 주소를 저장합니다. inode의 주소 슬롯은 `11 + 1 + 1 = 13`개를 유지하면서 마지막 슬롯을 이중 간접 블록에 사용합니다.

## 구현 내용과 주요 코드

- [fs.h](fs.h): `NDIRECT=11`, 이중 간접 블록 범위와 `MAXFILE`, 디스크 inode의 주소 배열
- [file.h](file.h): 메모리 inode의 주소 배열을 디스크 구조와 일치시킴
- [fs.c](fs.c): `bmap()`의 이중 간접 블록 할당·탐색, `itrunc()`의 데이터 및 간접 블록 해제
- [param.h](param.h): `FSSIZE=21113`으로 파일 시스템 이미지 크기 조정
- [mytest.c](mytest.c): 512-byte 블록을 반복 기록해 최대 파일 크기 확인

## 실행과 확인

빌드에 필요한 도구는 [루트 README](../README.md#빌드와-실행)를 참고합니다. inode의 블록 주소 해석이 바뀌므로 기존 파일 시스템 이미지를 재사용하지 않고 빌드합니다.

```sh
make clean
make CPUS=1 QEMU=qemu-system-i386 qemu-nox
```

xv6 셸에서 `mytest`를 실행합니다. 파일에 더 쓸 수 없을 때까지 512-byte 블록을 기록합니다. 최대 크기인 8,459,776 bytes를 쓰면 `wrote 16523 blocks`가 출력됩니다.

테스트는 최대 쓰기 크기를 확인합니다. 전체 데이터 재읽기와 삭제 후 블록 재사용 검사는 추가로 필요합니다. 당시 만점을 받았지만 Block Group까지 완성하지는 못했습니다.
